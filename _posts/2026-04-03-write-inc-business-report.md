## 왜 이 스킬을 만들게 됐나

프리랜서로 일하던 회사에서 맡았던 작업을 하면서, 필요한 자료를 넣으면 영업보고서 초안이 나오도록 만들 수 있지 않을까 생각했다.

영업보고서는 자료가 여러 군데 흩어져 있고, 최종 문서는 일정한 형식을 요구한다.  
그래서 생성형 AI로 문장을 길게 쓰게 하는 방향보다, 자료를 읽고 필요한 값을 구조화한 뒤 문서 형식으로 다시 조립하는 쪽이 더 맞다고 봤다.

반복적인 문서 작업을 조금 더 짧고 안정적으로 만들기 위해 `write-inc-business-report` 스킬을 직접 만들게 됐다.

## 스킬이란 무엇인가

여기서 말하는 스킬은 인공지능 에이전트가 특정 작업을 더 안정적으로 수행하도록 돕는 작업 패키지에 가깝다.  
지침, 코드, 체크리스트, 출력 형식, 템플릿 같은 것을 한데 묶어서 같은 작업을 반복 가능하게 만드는 방식이다.

OpenAI나 Anthropic 계열 도구에서도 비슷한 개념으로 쓰이고 있다.  
참고: [Claude의 스킬 설명](https://support.claude.com/ko/articles/12512176-%EC%8A%A4%ED%82%AC%EC%9D%B4%EB%9E%80-%EB%AC%B4%EC%97%87%EC%9D%B8%EA%B0%80%EC%9A%94)

## 영업보고서는 왜 늘 손이 많이 갈까

영업보고서는 한 번만 쓰면 끝나는 문서가 아니다. 회사의 개황, 주식 현황, 대주주, 임원, 재무 요약, 중요한 채권자, 결산기 후 중요 사실까지 여러 문서를 맞춰가며 다시 정리해야 한다.

특히 아래 같은 작업이 반복됐다.

- 같은 회사 정보를 매번 다시 옮겨 적기
- 발행주식 수, 자본금, 지분율이 서로 맞는지 다시 확인하기
- 손익계산서와 재무상태표 숫자를 보고 표를 다시 만들기
- 빈칸 없이 `해당 없음`과 `없음`을 통일해 채우기
- ZUZU 양식 느낌에 맞게 최종 `.docx`를 다시 정리하기

이런 작업을 조금 더 쉽게 줄이는 방향으로 스킬을 설계했다.

## 그래서 만든 스킬

이 스킬의 목표는 단순하다.  
영업보고서를 "잘 써주는 도우미"보다, 근거 문서를 읽고 사실을 정리한 뒤 같은 형식으로 안정적으로 다시 출력하는 도구로 만드는 것이다.

Workflow

1. 먼저 필요한 문서 세트를 모은다.
2. `docx`, `pdf`, `xls/xlsx`에서 텍스트를 뽑는다.
3. 회사명, 대상 기간, 보고일, 주식 수, 자본금, 임원, 재무 수치 같은 핵심 사실을 표처럼 정리한다.
4. 문서만으로 확정되지 않는 값만 짧게 다시 묻는다.
5. 문단, 불릿, 표 구조를 JSON으로 만든다.
6. `python-docx`로 ZUZU 스타일에 가까운 `.docx`를 렌더링한다.
7. 완성된 문서를 다시 열어 숫자와 이름이 원문서와 맞는지 검수한다.

회사명, 기간, 주식 수, 임원, 재무 수치처럼 문서의 뼈대가 되는 값을 먼저 정리해두면, 그다음 단계는 문장을 잘 쓰는 문제보다 문서를 일관되게 렌더링하는 문제에 가까워진다.

## 자동화하면서 가장 중요했던 기준

자동화 문서에서 제일 위험한 건 그럴듯한 추정이다.  
그래서 이 스킬에는 몇 가지 기준을 먼저 박아뒀다.

- 근거 없는 지분율 추정 금지
- 빈칸 금지
- 한 문서 안에서 `해당 없음`과 `없음` 표기 통일
- 주식 수, 액면가, 자본금은 서로 교차 검증
- 문서로 확인되지 않는 값은 묻고, 모르면 채우지 않기

출처 우선순위도 고정했다.  
가장 먼저 보는 건 유저가 준 기업 문서이고, 그다음이 현재 안건이나 회의 자료, 그다음이 회사 공식 사이트, 마지막이 유저 확인이다. 특히 주식 수, 지분율, 액면가처럼 숫자 하나가 문서 전체를 흔드는 값은 추정하지 않도록 했다.

구조도 일부러 단순하게 만들었다.  
최종 문서는 자유 서식이 아니라 `paragraph`, `bullets`, `table` 블록으로만 구성한다. 이 방식으로 잡으니 "문장을 어떻게 쓸까"보다 "이 정보가 표인지, 문단인지, 불릿인지"를 먼저 결정할 수 있었다.

## 사용 방법 가이드

이 스킬은 아무 문장 하나만 넣는 방식보다, 필요한 자료를 같이 넣었을 때 제대로 동작한다.  
기본적으로 아래 자료를 준비하는 흐름을 상정했다.

- ZUZU 영업보고서 템플릿 `.docx`
- 손익계산서
- 재무상태표
- 계정별원장 또는 합계잔액시산표
- 정관
- 주주명부
- 현재 회의 안건이나 보고일 정보

실행 흐름은 단순하다.

1. 영업보고서에 필요한 자료 파일을 한 폴더에 모은다.
2. 스킬이 각 파일에서 텍스트를 읽는다.
3. 회사명, 기간, 주식 수, 지분율, 자본금, 임원, 재무 수치 같은 핵심 값을 먼저 정리한다.
4. 자료만으로 확정되지 않는 값이 있으면 짧게 다시 묻는다.
5. 최종 내용을 JSON 구조로 만든 뒤 `.docx`로 렌더링한다.
6. 완성된 문서를 다시 열어 숫자와 이름이 맞는지 확인한다.

이 스킬에서 실제로 중요하게 보는 값도 비교적 분명하다.

- 회사명 / 영문명
- 보고서 제목 / 기수
- 대상 기간
- 보고일
- 본점 주소
- 발행주식총수 / 발행주식 수 / 액면가 / 자본금
- 대주주 이름 / 보유주식 수 / 지분율
- 이사 / 감사 / 직책
- 손익계산서 및 재무상태표 주요 수치
- 중요한 채권자
- 결산기 후 중요한 사실

출력은 `paragraph`, `bullets`, `table` 블록으로 구성된 JSON을 거쳐 `.docx`로 만들어진다.  
예를 들면 표 제목, 컬럼, 행 데이터가 이런 식으로 들어간다.

```json
{
  "type": "table",
  "title": "1) 회사 개요",
  "headers": ["구분", "내용"],
  "rows": [
    ["상호", "주식회사 예시"],
    ["설립일", "2025년 3월 25일"]
  ]
}
```

렌더링은 `python-docx` 기반 스크립트로 처리한다.

```bash
uv run --with python-docx scripts/build_report_docx.py \
  --input report.json \
  --output out.docx
```

완성 후에는 문서를 다시 열어 아래 항목을 보는 식으로 마무리한다.

- 기간이 첨부 자료와 맞는지
- 주식 수와 자본금 계산이 맞는지
- 지분율 합계가 자연스러운지
- 임원 이름과 직책이 최신인지
- 빠진 항목이 없는지

즉, 사용법 자체도 복잡한 AI 프롬프트라기보다, 자료를 모으고, 값을 고정하고, 문서를 렌더링하고, 마지막에 검수하는 흐름에 가깝다.

## 이 스킬로 줄이고 싶었던 일

아직 이 스킬의 효과를 장기간 실무에서 검증한 단계는 아니다.  
다만 만들면서 분명히 줄이고 싶었던 지점은 있었다.

- 자료를 읽고 필요한 값만 다시 추리는 시간
- 표를 복붙하면서 형식이 무너지는 시간
- 숫자와 이름이 앞뒤에서 다르게 적히는 실수
- "이번에는 어떤 항목을 꼭 넣어야 하지?"를 다시 확인하는 시간

즉, 문서를 완전히 대신 써주는 것보다 체크리스트와 출력 형식을 먼저 고정해두는 쪽에 더 가깝다.

## 아직 사람 확인이 필요한 부분

물론 이걸로 법률 검토까지 끝나는 건 아니다.  
이 스킬은 문서 자동화 도구이지, 법률 자문 도구는 아니다.

그래서 마지막에는 여전히 아래를 본다.

- 보고일, 대상 기간이 실제 자료와 맞는지
- 임원 이름과 직책이 최신 상태인지
- 중요한 채권자와 결산기 후 중요  사실이 빠지지 않았는지
- 회사가 원하는 실제 표기와 템플릿 문구가 맞는지

즉, 반복 업무는 자동화하되 최종 책임이 필요한 부분은 사람이 본다. 이 경계를 명확히 두는 게 오히려 더 중요했다.

## 마무리

`write-inc-business-report`를 만든 이유는 단순했다.  
반복적으로 들어가는 문서 작업을 조금 더 빠르고 덜 번거롭게 만들고 싶었다.

정리하면 이 스킬은 문서를 대신 "잘 써주는" 도구라기보다,  
흩어진 기업 자료를 읽고, 필요한 사실을 구조화하고, 반복되는 보고서 형식으로 안정적으로 다시 내보내는 도구에 가깝다.

반복되는 문서 작업일수록 사람의 판단은 뒤로 보내고, 형식과 검수 기준은 앞으로 당겨야 한다. 이 스킬은 그 기준을 코드로 옮긴 첫 번째 버전이다.

참고 및 출처
- 문서 구성과 템플릿 방향은 ZUZU 영업보고서 자료를 참고했습니다.
- 템플릿 사용 관련해서는 사전에 허락을 받고 반영하였습니다.
