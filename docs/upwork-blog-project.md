## 레퍼런스 스타일 확장본

### Title
`Technical Blog for Django, DevOps, and Automation`

### My role
`Developer, technical writer, and site maintainer`

### Project description
`Goal: Build a practical engineering blog that publishes clear notes on deployment, monitoring, automation, and AI-assisted development workflows.`

`Solution: I structured the site as a Jekyll-based knowledge base, maintained the writing and publishing workflow, connected the site to a custom domain, and kept delivery automated through GitHub Pages and GitHub Actions. I also organized posts so the blog can work both as a public reference and as a portfolio of hands-on technical problem solving.`

`Impact: The result is a maintainable technical blog that presents my work in a clearer way, makes past implementation records reusable, and gives clients or collaborators a fast way to review how I approach DevOps, automation, and system-oriented development tasks.`

### Project Overview
The project was to build and maintain a personal technical blog at `juwonpark.me` focused on Django, DevOps, automation, and data workflows. Rather than using the site as a simple profile page, I treated it as a working archive for deployment notes, monitoring setups, AI tool experiments, and troubleshooting records.

### Responsibilities
- Planned the blog structure and content direction around Django, DevOps, automation, and data workflow topics.
- Wrote and maintained technical posts based on real implementation and debugging sessions.
- Managed the Jekyll-based publishing workflow and custom-domain setup.
- Kept deployment automated with GitHub Pages and GitHub Actions.
- Used the blog as a long-term reference archive for reusable engineering notes.

### Challenges Faced
- Keeping the site useful as both a personal brand page and a real technical knowledge base.
- Maintaining a clean publishing workflow without turning the blog into a generic template site.
- Organizing technical notes so they stay readable for clients while still being detailed enough for engineering reference.

### Solution
I positioned the blog around short, practical write-ups rather than broad essays. The site uses a lightweight Jekyll workflow, a custom domain, and automated publishing so maintenance stays simple. Content is organized around concrete technical themes such as deployment, observability, automation, and implementation troubleshooting, which makes the blog more useful as proof of work.

### Impact
- Created a public-facing technical archive tied directly to my real engineering work.
- Improved how my DevOps and automation experience is presented to potential clients.
- Made previous build, deployment, and debugging notes easier to reuse across future projects.
